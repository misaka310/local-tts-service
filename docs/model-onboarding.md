# モデル追加チェックリスト

TTS / RVCモデルを30へ追加するときは、推論が動くだけでは完了にしない。次の項目を同じ変更で揃える。

## 1. 公式情報

- 公式モデルID / 配布ページ
- 公式コードリポジトリ
- 使用するコードrevision / モデルrevision
- 対応言語
- 参照音声・参照テキストの要否
- モデル固有の入力・調整機能
- 推奨VRAM / RAM / dtype / 実行環境など、利用可否を左右する条件

## 2. 利用条件

一次情報を確認して、少なくとも次を `frontend/public/model-catalog.js` の `MODEL_METADATA` と関連docsへ記録する。

- ライセンス名
- 商用利用条件
- 再配布・派生物・生成物に関する主要条件
- 禁止・制限事項
- 公式利用条件URL
- 参照音声・学習素材など第三者権利が別途必要な場合の注意

ライセンス名だけで「商用可」と短絡しない。モデル重み、コード、ベースモデル、codec、追加学習データで条件が異なる場合は併記する。

## 3. 実装

- 既存モデルと依存関係を衝突させない
- availability判定を追加する
- モデルの能力とUIの入力項目を一致させる
- 未導入・条件不足時は選択不可にして具体的な理由を表示する
- 利用条件の表示は既存の「使い方」内ライセンス欄へ追加し、通常生成・モデル比較など別画面へ新しい表示を増やさない
- 「使い方」のライセンス欄は `MODEL_ORDER` と `MODEL_METADATA` から自動表示する。商用区分は `commercialStatus` に明示し、自由文から推測しない。同じ配布モデル/チェックポイントの実行プロファイルは `licenseGroup` で1行にまとめ、別チェックポイント・別配布物だけ別行にする。表示はコンパクトにし、詳細説明はリンク先へ委ねる
- 「使い方」のライセンス欄から公式利用条件を確認できる

## 4. 実機検証

参照音声対応モデルは、実際の登録済み参照音声を使って新規WAVを生成する。

- API/通常経路の生成成功
- 参照音声が実エンジンまで渡っていること
- 新規WAVであること
- duration / sample rate / channels / RMS / peak / SHA-256
- 無音でないこと
- GPUモデルとVRAM使用状況
- 必要なら聞き取りまたはASRで入力内容を確認

## 5. 回帰

- Pythonのモデル固有テスト
- API / config回帰
- frontend `npm run check`
- frontend `npm test`
- `MODEL_ORDER` の実モデルは `MODEL_METADATA` 必須。内部テスト用 `mock` だけを例外とする

上記のいずれかが未完了なら「モデル追加完了」と扱わない。
